# ColdChainRx — Threat Model & Security Hardening (Week 7)

This document outlines the security architecture of the ColdChainRx platform, following the STRIDE threat modeling framework, and highlights the specific mitigations applied to the verification portal.

## STRIDE Threat Model

| Threat Category | Example Attack Scenario | System Mitigation |
| :--- | :--- | :--- |
| **Spoofing** | An attacker tries to submit fake telemetry masquerading as an authorized edge node (ESP32). | **Blockchain Layer:** Fabric CA ensures only nodes with valid X.509 certificates generated by the Manufacturer/Distributor MSP can invoke the `RecordTempReading` chaincode function. |
| **Tampering** | A malicious distributor tries to alter past temperature logs to hide an excursion. | **Blockchain Layer:** Hyperledger Fabric's immutable ledger makes history alteration computationally infeasible. All updates create a new state, and the history is queryable via `GetProvenanceHistory`. |
| **Repudiation** | A pharmacy claims they never received a compromised batch. | **Blockchain Layer:** The `TransferCustody` function requires the digital signature of the receiving organization (Pharmacy MSP) to commit the transaction to the ledger, enforcing non-repudiation. |
| **Information Disclosure** | Competitors attempt to scrape the public portal to deduce production volumes. | **Application Layer:** Rate limiting (max 100 requests / 15 mins) prevents mass scraping of `/api/batches`. Additionally, Fabric's Private Data Collections conceal commercial agreements. |
| **Denial of Service (DoS)** | Botnets flood the verification portal with random `batchId` requests to exhaust server resources. | **Application Layer:** Express `helmet` middleware secures HTTP headers, and `express-rate-limit` explicitly throttles the `/verify` endpoint (20 requests / 5 mins). Payload sizes are limited to 10kb. |
| **Elevation of Privilege** | An attacker injects NoSQL/SQL payloads into the QR search bar to dump the database. | **Application Layer:** Strict input validation enforces `batchId` to be alphanumeric with hyphens (max 30 chars), blocking malicious characters client-side and server-side. |

## Application Hardening Applied (Verification Portal)

1. **Helmet Middleware:** Secures Express apps by setting various HTTP headers (e.g., `X-Content-Type-Options: nosniff`, `Strict-Transport-Security`).
2. **Rate Limiting:** Protects `/api/*` against brute-forcing and DoS by restricting excessive hits from the same IP address.
3. **Input Sanitization:** Client-side React checks and server-side Express middleware enforce strict regex `/^[A-Za-z0-9\-]{3,30}$/` on all `batchId` queries.
4. **Payload Limiting:** JSON body payloads are restricted to a maximum of 10kb to prevent oversized payload attacks.
5. **CORS Configuration:** API endpoints explicitly restrict origins to `http://localhost:3000` (Next.js) for localized deployment.
